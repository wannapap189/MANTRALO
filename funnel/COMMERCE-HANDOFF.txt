MANTRALO - เส้นทางหนังสือ คอร์ส และการขอตรวจเครดิต
สถานะ: เตรียมการเชื่อมในเครื่องเท่านั้น ไม่มีการแก้เว็บไซต์จริง ไม่มี full-site export/ZIP/LLMS/GitHub ในงานนี้
เอกสารนี้เป็นแผนและรายการเชื่อมต่อ ไม่ใช่การยืนยันว่า Traffio API, payment events หรือ native import ทำงานแล้ว

สิ่งที่ทำงานในต้นแบบแล้ว
- หน้าแรก #/ เชื่อมไปฝึก #/start, คู่มือ #/library, หนังสือ #/book และคอร์ส #/course
- หน้าหนังสือมีเล่มจริงและตัวเลือกดิจิทัล; CTA เปิดสรุปรายการก่อนดำเนินการ
- หน้าคอร์สมี CTA สมัครคอร์ส และ modal ขอตรวจเครดิตแยกกัน
- app.js เรียก MANTRALO_FUNNEL.resolveAction(kind) ใน modal ของ book/digital/course/upgrade
- connection.js ใช้ข้อมูลสาธารณะที่ตั้งไว้เท่านั้น ไม่มี fetch, form submission, API, cookie, localStorage หรือการคำนวณสิทธิ์
- เมื่อยังไม่ตั้ง URL จะคงการสอบถามด้วย LINE ID @emcthai ไม่มีการส่งข้อความอัตโนมัติ
- ผลจักระ 14 หน้าอ้าง route-map.json โดยเก็บ URL/pageId/funnelId เดิมครบ
- ราคาหน้าเว็บรอบนี้คงหนังสือ/Starter 290 บาท คอร์ส 2,900 บาท เครดิตสูงสุด 290 บาท ไม่รับ price override จาก config

การตั้งค่า runtime
connection-config.example.js เป็นตัวอย่างที่ยังไม่ได้โหลดในต้นแบบ
หากภายหลังยืนยันการเชื่อม ให้ใช้ window.MANTRALO_FUNNEL_CONFIG ก่อนโหลด connection.js และโหลด connection.js ก่อน app.js
รับเฉพาะ schemaVersion, mode, actions และ systemLinks; ไม่รับราคา สิทธิ์เครดิต ลูกค้า email/token/secret หรือค่าเปิดสมาชิก
mode='inquiry': คงการสอบถาม ไม่มีลิงก์ดำเนินรายการจาก config
mode='connected': แสดงลิงก์เฉพาะ action ที่ URL ผ่านการตรวจรูปแบบแล้ว; ค่าอื่นที่ว่างยังคง fallback แยกได้
actions.book = URL สั่งหนังสือจริง 290 บาทและค่าส่งที่ยืนยันแล้ว
actions.digital = URL สั่ง Starter ดิจิทัลที่ยืนยันไฟล์และวิธีรับแล้ว
actions.course = URL สมัครคอร์สข้อเสนอ 12 บท 2,900 บาทที่ยืนยันแล้ว
actions.upgrade = URL หน้าขอตรวจรายการซื้อ/เครดิตในระบบเดิมเท่านั้น ไม่ใช่ URL checkout ลดเหลือ 2,610
systemLinks.orderStatus/memberLibrary/courseDashboard = ช่องอ้างอิงปลายทางระบบเดิม; ตอนนี้ runtime อ่านได้แต่ยังไม่มี UI เรียกใช้งาน

ผลคืน resolveAction(kind)
configured: มี URL HTTPS ที่ตั้งไว้และผ่าน validator พร้อม label/actionType; app จึงแสดงลิงก์ใน modal ผู้ใช้กดเอง
unconfigured: ไม่ตั้ง config, อยู่ inquiry mode หรือ URL ว่าง; app ใช้ข้อความและ LINE fallback เดิม
invalid: config มี field ไม่รองรับ, URL ผิดรูปแบบ/local/placeholder, URL endpoint ข้อเสนอเก่าที่ระบุไว้, query/fragment ไม่รองรับ หรือ upgrade ชี้ checkout; app ไม่แสดงลิงก์ผิดและยังใช้ fallback
configured หมายถึงตั้งค่า navigation แล้ว ไม่ได้แปลว่า URL ออนไลน์ ราคา backend ถูกต้อง จ่ายเงินแล้ว หรือผู้ใช้มีสิทธิ์
ตัว validator ไม่ส่ง request เพื่อทดสอบปลายทาง จึงไม่รู้กรณี 404/ระบบล่ม/หมดเวลา ผู้ใช้กลับมาสอบถามผ่านช่องทางเดิมได้

ขอบเขต URL
- absolute HTTPS เท่านั้น ไม่รับ credentials ใน URL หรือ host local/IP/placeholder
- query รับเฉพาะ lang, locale, productId, variantId, sku โดยแต่ละค่าเป็นตัวอักษรอังกฤษ/ตัวเลข/ขีด/ขีดล่าง 1-100 ตัว และแต่ละ key ไม่ซ้ำ
- การอนุญาตชื่อ query เป็นเพียงการตรวจ public navigation reference ไม่ใช่การเดาว่า Traffio ใช้ parameter เหล่านี้; ไม่สร้างหรือต่อ query ให้เอง
- หาก URL จริงใช้ query อื่น ต้องตรวจความหมายจากระบบก่อนปรับ allowlist ไม่ใส่ token, email, phone, amount, credit หรือ eligible เพื่อให้ลิงก์ผ่าน
- fragment รับเพียงเส้นทาง #/route แบบตัวอักษรอังกฤษ/ตัวเลข/ขีด/ขีดล่าง ไม่รับ query หรือ OAuth token ใน fragment
- ไม่เติมอัตโนมัติด้วย #/book หรือ checkout เดิมที่ราคา/ข้อเสนอไม่ตรง
- หน้าเดิม unlockchakra.emcthai.com เป็นแหล่งข้อมูลคอร์ส 15 บท ไม่ใช่หลักฐานว่าสิทธิ์ข้อเสนอใหม่ 12 บทพร้อมใช้

เส้นทางขายที่เตรียมไว้
หนังสือ: หน้าผล/หน้าแรก -> #/book -> สรุปเล่มจริง+E-book 290 -> URL สั่งซื้อที่ยืนยัน -> ระบบเดิมแสดงค่าส่งและยอดรวม -> ระบบเดิมยืนยันออเดอร์/สิทธิ์อีบุ๊ก
ดิจิทัล: #/book เลือกดิจิทัล -> สรุป Starter 290 -> URL สั่งดิจิทัลที่ยืนยัน -> ระบบเดิมชำระ/ส่งสิทธิ์ ไม่ส่งเล่มจริงโดยอัตโนมัติ
คอร์สโดยตรง: #/course -> สรุปคอร์ส 12 บท 2,900 -> URL สมัครที่ยืนยัน -> ระบบเดิมชำระ/เปิดสิทธิ์คอร์สและ Starter ดิจิทัล ไม่ส่งหนังสือเล่มอัตโนมัติ
อัปเกรด: #/course -> ขอตรวจเครดิต -> URL หน้าตรวจในระบบเดิมหรือผู้ดูแลตรวจ -> แจ้งเครดิตจริงและยอดส่วนต่าง -> ผู้ใช้ยืนยันชำระในระบบเดิม -> เปิดสิทธิ์หลังยืนยันการชำระ
ผลที่คำนวณบนหน้าเว็บ 2,900 - 290 = 2,610 เป็นตัวอย่างเต็มเครดิตเท่านั้น ไม่มี checkbox หรือ URL parameter ให้ผู้ใช้รับสิทธิ์เอง
หน้า result ไม่สร้างออเดอร์/contact ใหม่ และไม่มี auto-redirect ไปชำระเงิน

รายการที่ผู้ดูแลระบบต้องยืนยันก่อนเชื่อมจริง
1. URL สำหรับ book, digital, course และหน้าขอตรวจเครดิต พร้อม native product/page references ที่มีจริง; ขณะนี้ยังเว้นว่าง ไม่กำหนด ID ใหม่เอง
2. หนังสือ: ค่าส่ง/วิธีส่ง/กำหนดส่ง, E-book เต็มฉบับที่แถม, วิธีให้สิทธิ์หลังยืนยันยอด
3. คอร์ส: playlist 12 บทที่จะให้จริง ระยะเวลาเข้าเรียน วิธีเข้าระบบเดิม และ Starter ดิจิทัลที่รวม
4. เครดิต: แหล่งออเดอร์ที่ตรวจได้ การจับคู่กับบัญชีเดิม บันทึกการใช้เครดิตครั้งเดียว และกรณียกเลิก/คืนเงิน
5. ปลายทางตรวจสถานะออเดอร์ คลังสมาชิก ห้องเรียน และผู้รับผิดชอบกรณีระบบผิดพลาด
6. ความสามารถ code block/HTML/script/CSP และ lifecycle ของ Funnel เดิม ยังไม่ยืนยันการรองรับ
ห้ามใช้ config สาธารณะเก็บ credentials หรือข้อมูลลูกค้า; การจับคู่ contact/tags/members ใช้ระบบเดิม ไม่มีการ import หรือสร้างข้อมูลซ้ำจากต้นแบบนี้

สถานะธุรกรรมและสิทธิ์ - แผนงานเท่านั้น ยังไม่มี listener/webhook/automation ทำงาน
payment_pending: ระบบเดิมยังรอชำระ; แสดงช่องทางตรวจสถานะจริง ห้ามขึ้นว่าซื้อสำเร็จหรือปลดล็อก
payment_failed/cancelled: คงสถานะจากระบบเดิม ผู้ใช้ตรวจรายการหรือขอความช่วยเหลือ ไม่สร้างออเดอร์/รายชื่อซ้ำอัตโนมัติ
payment_confirmed: ต้องมาจากข้อมูลยืนยันของระบบรับชำระ/ออเดอร์เดิมเท่านั้น จึงดำเนินการส่งมอบ/ให้สิทธิ์ตามสินค้าที่ซื้อ
credit_review_pending: ยังไม่ยืนยันเครดิต ไม่มีราคาส่วนลดเฉพาะบุคคล
credit_manually_verified: ผู้ดูแลตรวจยอดสินค้าที่เข้าเงื่อนไขตามการซื้อจริง สูงสุด 290 ไม่รวมส่ง/Office/สินค้าเพิ่ม และตรวจว่ายังไม่เคยใช้ ยกเลิก หรือคืนเงิน; บันทึกผลในระบบเดิมก่อนแจ้งยอด
credit_not_eligible: แจ้งเหตุผลจากการตรวจและทางเลือกเรียนราคาเต็ม ไม่เปลี่ยนประวัติหรือสิทธิ์จากหน้าเว็บ
upgrade_payment_confirmed: หลังยืนยันยอดส่วนต่าง ระบบเดิมบันทึกการใช้เครดิตและสิทธิ์คอร์สครั้งเดียว ไม่เพิ่มซ้ำเมื่อ refresh หรือได้รับ event ซ้ำ
refund/reversal: ระบบเดิม/ผู้ดูแลพิจารณาปรับสิทธิ์และรายการเครดิตตามนโยบายจริงที่กำหนดก่อนขาย ไม่คืนเครดิตหรือเพิกถอนสิทธิ์อัตโนมัติจาก config/URL
ไม่มีชื่อ event/API จริงของ Traffio ถูกกำหนดขึ้นในเอกสารนี้; ชื่อสถานะข้างบนเป็น vocabulary สำหรับตกลงงานหลังบ้าน
ห้ามเชื่อ ?paid=true, ?credit=290, hash, localStorage หรือคำสั่งจาก browser เป็นหลักฐานชำระเงินหรือยืนยันสิทธิ์

วิธีตรวจในเครื่องโดยไม่กระทบข้อมูลจริง
- เปิด home/start/library/book/course และตัวอย่างผลครบ 14 หน้า
- ค่าเริ่มต้น inquiry: modal แสดงสรุป+ช่องทางสอบถาม ไม่มีการนำไป checkout
- ตรวจ validator ใน Node VM ด้วยข้อมูลสังเคราะห์เท่านั้น ไม่มีการเปิด URL หรือส่งข้อมูล
- root ตรวจมือถือและความสามารถใช้งานจริงของ modal; งานนี้ไม่ได้ทดสอบการชำระเงินหรือหน้า admin
- เมื่อได้รับ URL จริงในภายหลัง ให้ตรวจปลายทางและข้อเสนอในสภาพแวดล้อมที่ระบบอนุญาตก่อนเชื่อม; ไม่ใช้การส่งคำตอบ/สร้างลูกค้าจริงเป็นการทดสอบต้นแบบ

production-config.example.json: config เฉพาะเครื่องมือ result14 เดิม แยกจาก connection-config.example.js; export-traffio.mjs ไม่ได้ส่งออกทั้งเว็บหรือเพิ่ม runtime commerce อัตโนมัติ
